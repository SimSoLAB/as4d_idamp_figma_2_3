# iDAMP.repair Working System Architecture

This repository is the controlled development source for the working-system implementation. Figma-originated code and visual output are reference inputs; they are not Company Truth owners.

## Strategic journey

Curiosity → Trust → Competence → Proof → Integrated System → Deep Evidence → Explicit Action.

## Industrialisation story

Specialist technology/evidence → aS4D repair industrialisation → scan/application intelligence → installed industrial LPBF → customer-local validation/qualification.

## Controlled content

UI content is classified as `STRATEGIC_INTENT`, `CURRENT_FACT`, `INVESTOR_FRAMING`, `FORWARD_LOOKING`, `EVIDENCE_GATED`, or `PLACEHOLDER`. Technical claim release remains outside this repository and subject to CURRENT Product & Technology, Claim Register and `HOLD-TECH-T2B`.

## Impact Intelligence

The semantic event contract is versioned and session-memory only. Duplicate collapse happens before sequence assignment. Journey reconstruction works from actual emitted events. Passive behavior is not converted into lead score, buying intent, pipeline truth or person identity.

## Explicit action

A `whitepaper_request` event is emitted only after required-field and email validation. No backend submission is simulated.

## Open gates

Production measurement/persistence, privacy/legal, consent, vendor selection, deployment/publication and any person-level linkage remain separate OPEN gates.
